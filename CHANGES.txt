Implementation decisions
The header reserves 1024 bytes. Each block reserves 64 bytes for count and links.
Minimum occupancy is measured against the bytes available for record payloads.
RBNs start at zero and -1 marks the end of a list.
Block size defaults to 512 and minimum occupancy to 50 percent. Both are
command-line settings and are stored in the header. The supported minimum
range is 1 through 50 percent.

With indivisible variable-length records, some combinations cannot be divided
into two blocks that both satisfy an exact byte occupancy threshold. Such an
update is rejected without changing the original pair. A lower configured
minimum can accommodate these cases. Oversized records are also rejected.

Addition and deletion batches are performed on a temporary disk copy, then
validated and committed with backup files for rollback on ordinary I/O errors.
This keeps RAM use bounded but copies the disk file once per batch. Use one
writer at a time. The paired rename is not a power-failure-atomic transaction.
If execution is interrupted during commit, inspect the .bak data and index pair
before starting another writer.

The companion filename is derived from the data filename and recorded in the
header. Version 3 files produced by this program use the schema described there.
